4. Bug / Issue Report

Bug IDModuleIssueSeverityStatusRecommendation
BUG-001Pricing / stockConfirmed Issue: A published product (id 3) quotes MRP 427.5 but sale_price 0. Placement still creates a non-scheme line, deducts batch qty, and can be marked paid with grand_total 0. HighOpen OrderPlacementService.php → buildBackendLines() → Reject paid lines with sale_price <= 0 unless is_manual_scheme is explicit. Optionally warn in create.blade.php picker when quoted sale is 0.
BUG-002CreditConfirmed Issue: Customer search returns credit_limit / credit_status / credit_days, but OrderPlacementService never checks credit before placing a backend order. HighOpen OrderPlacementService.php → placeFromBackendRequest() → Enforce credit_status/limit (or an explicit override checkbox) before writeOrderDetails().
BUG-003CompanyConfirmed Issue: store() requires company_id (exists:companies) and merges order_company_code into the number, but orders has no company_id column and the service never stores the selected company as a foreign key. MediumOpen If the company must be auditable, add persistence (schema change only if the user requests a migration) or store company code on a dedicated order column. Today the only durable link is the code prefix (e.g. C-00001-S-26-27-1).
BUG-004UIConfirmed Issue: Local delivery client validation calls preventDefault but does not return, so Create Order still submits. MediumOpen create.blade.php → submit handler (~line 3212) → add return; Server-side resolveLocalDeliveryPartner still blocks empty partner.
BUG-005AttachmentsConfirmed Issue: Files are stored to disk before placeFromBackendRequest(); order attachments are created after the placement transaction. A mid-loop failure can leave an order without all files (files are deleted only on placement exceptions). MediumOpen OrderController.php → store() → Create attachments inside the same DB transaction as placement, or move file+row writes into OrderPlacementService.
BUG-006TransactionsConfirmed Issue: runAfterPlacementHooks (email, wallet reward, notifications) runs after DB::transaction commits. Paid-order side effects are not rolled back with the order. MediumOpen OrderPlacementService.php → placeFromLines() → Keep financial side effects in-transaction or dispatch queued jobs only after a successful commit with idempotency keys.
BUG-007XSSConfirmed Issue: Line hidden inputs concatenate fieldValue without escapeHtml. A quote in variation/base_sale_price can break the form or inject markup. MediumOpen create.blade.php → renderLines() hidden input builder → escape attribute values (escapeHtml) the same way visible cells are escaped.
BUG-008GST / discountConfirmed Issue (live): 10% additional discount of 11.900 reduced taxable value to 107.100 but GST stayed 5.950 (5% of the pre-discount 119). Grand total 113.050. Same numbers on the order show page Final column. HighOpen OrderPlacementService.php → applyBackendAdditionalDiscount() / summarizeLines() → Recalculate line GST from the discounted taxable amount (or document that additional discount is post-GST and stop labeling 107.100 as Taxable Value).
BUG-009CustomerConfirmed Issue (live): Selected customer NEW UNISONS PHARMA shows Drug Licence Expiry 25-08-2022. Order date 03-09-2026 still allowed. No warning or block. MediumOpen create.blade.php customer card + OrderPlacementService.php → Warn or block when DL expiry is before order_date unless overridden.
BUG-010Order showCompany showed “—” while order number used C-00001. Retest: show2 now prints issuing_company_label_for_order() → nexgeno technology (C-00001). MediumClosed resources/views/backend/sales/show2.blade.php → Company row; Helpers.php → issuing_company_label_for_order().

16. Testing Limitations

  • This rerun did not place a new order. GST, credit, and zero-PTS defects were not re-executed as new placements; BUG-008 remains evidenced by order 21 list total ₹113.05.
  • Live happy-path (earlier) used local delivery (Blinkit), not courier live rates or file uploads. Mobile/tablet viewports were not tested.
  • A real unpaid order C-00001-S-26-27-1 remains in the local database from the first live session. Cancel or edit it if it should not remain.
  • Customer search requires at least 2 characters (a single letter returns nothing by design).
  • Guest access was verified in Chrome (redirect to /login). Other browsers/devices were not tested.
  • Live HTTP store() happy path was completed (unpaid, no attachments). Consignee-copy uploads and courier rate APIs were not exercised.
  • An earlier service-layer paid placement (rolled back) may still have invoked after-commit email/notification hooks.
  • No production credentials or HTTPS endpoint were used.

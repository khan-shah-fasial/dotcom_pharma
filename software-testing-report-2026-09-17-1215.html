4. Bug / Issue Report

Bug IDModuleIssueSeverityStatusRecommendation
BUG-001PricingDiscount Master is CRUD-only. Cart, checkout, and backend order placement never read discount_masters. Saving an “Active” offer does not change price, points, scheme free qty, or invoice discount. CriticalOpen OrderPlacementService.php → placement/pricing → introduce a single apply-Discount-Master step (with date, status, role, qty slab, and target match). Until then, show a clear admin notice that records are not applied to orders.
BUG-002SaveRequired integer IDs can be junk. find() then stores null, so Applied On can be SKU/batch with no product. HighOpen DiscountMasterController.php → payloadFromRequest() → validate exists:product_stocks,id / exists:product_batches,id and abort if the resolved model is null.
BUG-003Form mathAmount, scheme, and effective rate do not match the field labels. Scheme buy qty defaults to 50. Scheme Value is overwritten. Amount-wise uses product rate. Flat > rate writes percent > 100 and can fail validation. HighOpen _form_script.blade.php → recalc() → compute from the selected type only; do not default qty to 50; do not force scheme_value; keep derived percent out of the posted value_percent when type is flat.
BUG-004Listing filtersDate filters do not mean “active during this range”. A discount from 2020–2030 is excluded if From Date filter is 2026. HighOpen DiscountMasterController.php → index() → use overlap logic on from_date / to_date.
BUG-005CombinationsAny Discount Type can be saved with any Applied On. Batchwise-on-category and amount-wise-on-SKU are legal records with no defined meaning. HighOpen DiscountMasterRequest.php → rules() → encode the allowed matrix; hide illegal types in _form_script.blade.php.
BUG-006DeleteDestroy is a GET route. The confirm modal follows that GET href. An authenticated admin who opens a crafted link deletes the row (same CMS pattern as flash deals, still unsafe). HighOpen routes/admin.php → discount master group → change destroy to DELETE/POST with CSRF. DiscountMasterController.php → destroy().
BUG-007SaveCategory / group / customer saves can keep a leftover effective_rate from the hidden role-price block. MediumOpen DiscountMasterController.php → payloadFromRequest() → null effective_rate with rate/amount for non-stock targets.
BUG-008SaveSchemewise keeps leftover value_amount / value_percent from a previously selected batchwise/productwise block. MediumOpen DiscountMasterController.php → payloadFromRequest() → clear value columns for schemewise unless they are part of the scheme.
BUG-009ValidationQty slab inversion, 0% / 0 amount, and fully empty schemewise rows are accepted. MediumOpen DiscountMasterRequest.php → rules() → add gte, gt:0, and “at least one scheme field”.
BUG-010Form restoreFailed save blanks typeahead labels. Deactivate can display as Active because @selected("0") is truthy in PHP. MediumOpen _form.blade.php → status options and typeahead value attributes → compare status as strings; rebuild labels from old IDs.
BUG-011Applied OnSKU Product and Full Variant are duplicate selectors for the same product_stocks row. Listing then shows SKU in one column or variant in the other, which looks like two different grains of discount. MediumOpen DiscountMaster.php → APPLIED_ON → collapse or implement true variant-wide matching.
BUG-012LookupsCreate form Stock Available for SKU uses the latest batch qty. Listing Stock uses product_stocks.qty. Same discount, two numbers. MediumOpen DiscountMasterController.php → lookupTarget() and DiscountMaster.php → sourceQty() → pick one source (stock vs batch) and use it on both screens.
BUG-013SaveCustomer/category/group IDs are not existence-checked. Lookup customers are approved only; save accepts any integer, including non-customers. MediumOpen DiscountMasterRequest.php → rules() → exists: plus approved-customer check reused from OrderPlacementService::approvedCustomerQuery().
BUG-014Listing UISixteen stacked header columns and a red Reset button. The table is the form laid on its side; it does not scan as a list. LowOpen index.blade.php → reduce to identity, type, target, value, dates, status, actions. Style Reset as secondary, not danger.
BUG-015CodesnextCode() takes the latest row by id, not max numeric suffix, and is not locked. Two concurrent saves of the same type can hit the unique discount_code constraint and 500. LowOpen DiscountMaster.php → nextCode() → compute MAX of the numeric suffix inside a transaction, retry on unique conflict.
BUG-016ListingRole-price grid is live from product/batch JSON, while Rate / Amount / Effective Rate are the saved snapshot. After a price change the row disagrees with itself. LowOpen index.blade.php → show saved rate as the source of truth, or label the grid “Current prices (not saved)”.
BUG-017Form“Category (Main)” and Group dropdowns load every category/group, including children. Hidden stocks are also returned by SKU lookup. LowOpen DiscountMasterController.php → formPayload() / lookupStocks() → restrict to parent categories if that is the business rule; exclude is_hidden stocks.
BUG-018FormCreate form “Date Of Add / Edit” is the page-load clock, not a saved timestamp. Switching Applied On SKU→batch can leave a hidden product_stock_id so save succeeds with an empty SKU box. LowOpen _form.blade.php and _form_script.blade.php → showAppliedOnFields() → blank unused hidden IDs; show Date Of Add only on edit from updated_at.

15. Final Status

Final Status

Not Ready for Production

Recommendation

  • What works: permissioned admin CRUD scaffolding, type-prefixed codes, applied-on required fields, date-order validation, search, pagination, table-missing guard, and scheme “other product” required when not same.
  • What must be fixed first: Discount Master does not participate in cart, checkout, or backend order pricing. Active rows are inert.
  • Critical/High still open: BUG-001 (no apply engine), BUG-002 (null targets), BUG-003 (nonsensical recalc), BUG-004 (date filters), BUG-005 (illegal type/target pairs), BUG-006 (GET delete).
  • Retesting is required after an apply engine exists and the form/filter bugs are fixed. Browser happy-path was not run because MySQL was down.
  • Production deployment of this module is not recommended if the business expects these offers to change invoices, points, or schemes.

16. Testing Limitations

  • Local MySQL (wampmysqld64) was Stopped. Schema::hasTable('discount_masters') and record sampling failed with connection refused.
  • Guest requests to /admin/discount-masters timed out instead of returning a login redirect, because the app could not reach the database.
  • No admin credentials were used. Create/edit/toggle/delete were not clicked in a browser.
  • Payment, storefront checkout, and backend Add Order were inspected in code for Discount Master usage only; no live order was placed.
  • Safari, Firefox, Edge, and mobile viewports were not tested.
  • Performance timings were not measured.
  • The user-journey note under .kilo/plans/ describes seller CRUD, bulk actions, and discount:deactivate-expired. Those are not in the shipped module. They were treated as plan text, not as confirmed product bugs, except where the current admin UI itself behaves incorrectly.
